Source: source L5/L7/L9/L11/L21/L23/L29, public fixture L6–L25. Design groups: `cpu.interface`, `cpu.structure`, `npu.interface`, `integration.boundary`.

`rv32i_five_stage_cpu #(parameter ENABLE_XNEBULA = 0)` is the base public module. Valid configurations are 0 and 1. Both use the same 32-bit datapath and five real stages. An explicit constant generate branch instantiates `nebula_npu_dot4` only when the parameter is 1. The disabled branch ties internal NPU handshakes inactive and decodes every custom-0 instruction as illegal; no unused multiplier must remain in the base synthesized hierarchy. ## 3. Clock, reset and state inventory

Source: source L7/L23/L27/L31; public fixture L42–L45/L102–L114. Design groups: `cpu.reset`, `cpu.pipeline`, `npu.cancel`.

Author choice: all sequential hardware uses the rising edge of `clk` and asynchronous active-low `rst_n` assertion, matching the provided instruction-memory reset style. The environment releases reset away from the active sampling edge and resets memories with the core. There is one clock domain, no derived/gated clock or CDC. Stage holds use clock enables. Kill is synchronous cancellation at an NPU edge, with combinational valid/ready suppression while kill is asserted; it is not a reset clock.

Reset state: fetch PC=0x80000000; all IF/ID, ID/EX, EX/MEM, MEM/WB valid bits=0; fetch held-data flag=0; data outstanding/request ownership flags=0; NPU adapter issued flag=0; NPU phase=IDLE; commit_valid=trap_valid=0; RF clears; mstatus=0x1800, mtvec=0x80000000, mscratch=mepc=mcause=mtval=0. Other payload registers may be cleared to zero as an author choice; validity is the sole authority for using payload. While reset is low, imem_valid, dmem_req_valid, dmem_rsp_ready, NPU req_valid/req_ready/rsp_valid/rsp_ready and commit_valid/trap_valid are suppressed. Address/data observation payloads clear to 0. Release initiates a fresh fetch from reset PC; no old response or instruction can become valid.

State and responsibility:

| State | Payload / purpose | Normal next-state rule |
| --- | --- | --- |
| fetch_pc | next sequential/redirect request address, 32 bits | accepted fetch: +4 modulo 2^32; eligible redirect: target; otherwise hold |
| IF/ID group | valid, request PC, held instruction word and held flag | accepted fetch replaces PC/valid and uses response bypass; blocked current response is captured once; consumed without replacement clears valid |
| ID/EX group | valid, PC, insn, rs indices/use flags, operand snapshots, imm, op, rd/write intent, CSR controls, exception descriptor | ID transfer replaces; EX transfer without replacement clears; blocked holds with WB operand refresh |
| EX/MEM group | valid, PC, insn, rd/write intent, result, original EA, aligned address, lane mask/data, memory kind, CSR old/new intent, exception descriptor | completed EX transfer replaces; MEM transfer without replacement clears; request/response wait holds |
| MEM/WB group | valid, PC, insn, rd/result/write intent, successful-store address/mask/data, CSR intent, exception descriptor | completed MEM transfer replaces; retiring/trapping consumes once; no replacement clears |
| mem_sent | EX/MEM request has handshaken | request fire sets; corresponding response fire or reset clears |
| xdot_issued | ID/EX owner has accepted an NPU request | NPU request fire sets; owner response transfer or cancellation clears |
| CSR bank | MIE, MPIE and the listed writable CSR fields | WB CSR operation / WB trap / WB MRET; otherwise hold |
| NPU phase/product/reduction/output | Section 12 | phase equations in Section 12 |
| event registers | commit/trap outputs | default valids=0 each edge; WB one-shot sets one event |

Exception descriptor is `(fault, cause[31:0], tval[31:0])` paired with the original instruction PC/word. Pipeline stage age defines priority; no reorder buffer, speculative store buffer, instruction cache or predictor is introduced.

## 4. Five-stage cycle contract and transfer rules

Source: source L21/L31/L33; acceptance L42/L48/L54–L55; public fixture L42–L87. Design group: `cpu.pipeline`.

At edge n the external registered instruction memory samples a request. Its nonblocking output becomes the requested instruction after n, remains available during the following cycle, and is sampled by ID at n+1. CPU must not sample the new nonblocking value in the same sequential block at n. The IF/ID group at n stores accepted request metadata; its instruction input during the following ID cycle is the paired external registered response, with a CPU held-word register selected during stalls. This timing reuse of the external synchronous read output avoids an extra internal response register in the steady path. The IF/ID group is real state, independent of ID/EX; it has PC/valid registers and an instruction hold register. Registering every instruction again before decoding would add an unauthorized cycle.

For an independent ordinary instruction:

| Edge / ensuing cycle | Real action for instruction fetched at n |
| --- | --- |
| n | IF request sampled; IF/ID request PC and valid registered; memory supplies response after edge |
| n+1 | ID consumes paired response; decoded controls/operands/PC/insn enter ID/EX |
| n+2 | EX computes and registers result/control into EX/MEM |
| n+3 | MEM nonmemory pass-through registers the instruction/result into MEM/WB |
| n+4 | WB consumes MEM/WB; RF writes and commit event register updates at this same edge |

Thus each ordinary instruction crosses four full cycles, five edges. Consecutive independent ADDIs issue at n,n+1,... and commit at n+4,n+5,...; the 64th commits 67 edges after the first fetch. There is no separate commit FIFO, delayed-valid line or early architectural RF write. Adjacent one-cycle commit events can appear as a continuously high commit_valid with a new payload each edge; this means one retirement per edge, not a repeated instruction.

Define `wb_consume = MEM/WB.valid` when reset is inactive; a WB normal token retires, a WB fault token traps. No external commit backpressure exists. Define `mem_done` as: EX/MEM invalid; or nonmemory token; or pre-detected fault; or its owned memory response handshakes. For a memory token with no response, mem_done is false even if the request just handshook. `mem_advance` also requires no older WB trap/MRET redirect. EX can advance when MEM can accept/relinquish its old token, operands are ready, no older fault is selected, and its NPU operation if any is complete. ID advances when EX can accept, there is no load-use interlock, no CSR serialization or older flush, and its IF/ID token is valid. IF issues only when its current response will be consumed or IF/ID is empty, no younger-fetch block applies, and the next address is aligned.

Every edge may consume an old token and replace it with the next token. Enables use pre-edge state and response signals, not freshly assigned sequential state. A stage with no transfer holds; a consumed stage without replacement becomes invalid. WB continues draining during younger MEM/NPU stalls. A held WB token must never commit repeatedly. For a MEM response, use the same edge to transfer completed memory to MEM/WB and advance a held younger EX token into EX/MEM when safe. Front-end resumes on that edge rather than after an extra recovery state.

Age/flush arbitration, author choice: reset first; oldest WB fault or WB MRET next; older MEM response fault next; current EX fault/control redirect next; interlock/serialization/NPU wait; ordinary transfers. A wrong-path ID fault is discarded when an older branch redirects. A MEM error suppresses younger EX redirect, NPU acceptance, data requests and advancement on the response edge; older normal WB may retire once on that edge. The MEM fault token then enters MEM/WB for trap on the next edge. Trap and normal commit are mutually exclusive for a single WB slot.

## 5. Fetch pairing, holds and redirects

Source: source L21/L23/L31; public fixture L42–L65. Design group: `cpu.fetch`.

Fetch accept is `rst_n && imem_valid` at the edge; there is no imem_ready or response-valid port. A valid accepted request alone creates a response token. Each token has its own request PC and one-cycle response pairing. Data with no matching token is ignored, even if imem_rdata retains a prior word.

Author choice: no fetch-ahead queue. A new request may replace IF/ID only when its current ID token will transfer at the same edge. If ID blocks, imem_valid drops before that edge. The current paired response is captured into the IF/ID held-word field at the first blocking edge, held flag sets, and subsequent decode uses the held word rather than unqualified imem_rdata. This works even if external data changes in cycles without requests; it does not require the environment to hold invalid data. There is capacity for the already accepted response and no unreserved future request. On resumed transfer, the held flag clears and replacement request metadata owns the next response. Fetch PC only increments for an accepted request, so a stall cannot lose or duplicate a PC.

Normal fetch requires fetch_pc[1:0]=0. Taken branch/JAL/JALR computes alignment in EX before redirect: an unaligned control target faults the control instruction (no link write), tval is that target, trap PC is the control instruction PC. A not-taken conditional branch does not fault merely because its unused target is unaligned. JALR clears bit0 first and then checks bit1. MRET target is aligned by mepc CSR masking. Reset and mtvec targets are aligned. A defensive fetch-PC alignment failure creates a fault token without a physical fetch; it is not a bus access error.

A legal taken control transfer clears younger IF/ID and any held response, changes fetch_pc to the target, and kills any accepted younger response token. Author choice: suppress imem_valid on the redirect edge and issue target next edge; any already accepted wrong-path response is discarded by invalidating ownership. A stall never overrides an older redirect. EX redirect does not discard the branch/jump itself or older stages; jump link PC+4 still enters EX/MEM. MRET redirects only at WB because it updates architectural status there. Trap uses the committed mtvec at WB, not a speculative CSR value. Redirect penalties are reported and have no additional source-imposed limit.

## 6. Decode and integer datapath

Source: source L9/L21/L25/L27; acceptance L24/L64. Design group: `cpu.decode`.

All PC, address, addition, subtraction and register results are 32-bit modulo arithmetic. Signed compare/arithmetic shift explicitly interpret operands as signed two's-complement. Unsigned compare interprets them as unsigned. Results of comparisons are 32-bit 0 or 1. Logical shifts zero-fill; arithmetic right shift sign-fills; register shift counts use rs2[4:0]. No arithmetic overflow trap.

Immediate construction (sign extension to 32 unless U): I=insn[31:20]; S={31:25,11:7}; B={31,7,30:25,11:8,0}; U={31:12,12'b0}; J={31,19:12,20,30:21,0}. CSR immediate is zero-extended insn[19:15], not sign-extended. For SLTIU, sign-extend I first and compare the resulting 32-bit unsigned value.

| Opcode | Legal funct / operation | EX behavior / writes |
| --- | --- | --- |
| 0x37 LUI | U | rd=U, no rs source |
| 0x17 AUIPC | U | rd=PC+U |
| 0x6f JAL | J | rd=PC+4; redirect PC+J after target check |
| 0x67 JALR | funct3=000 only | rd=PC+4; target=(rs1+I)&0xfffffffe |
| 0x63 branch | 000 BEQ,001 BNE,100 BLT,101 BGE,110 BLTU,111 BGEU | equality or signed/unsigned compare; target=PC+B; no rd |
| 0x03 load | 000 LB,001 LH,010 LW,100 LBU,101 LHU | EA=rs1+I; data processed in MEM; rd intent even for x0 but architectural write masked |
| 0x23 store | 000 SB,001 SH,010 SW | EA=rs1+S; forwarded rs2 determines bus data; no rd |
| 0x13 OP-IMM | 000 ADDI,010 SLTI,011 SLTIU,100 XORI,110 ORI,111 ANDI | rd=specified operation on rs1 and I |
| 0x13 shifts | 001 with insn[31:25]=0 SLLI; 101 with 0 SRLI or 0x20 SRAI | rd=shift(rs1,insn[24:20]); other upper shift encodings illegal |
| 0x33 OP | funct7=0: 000 ADD,001 SLL,010 SLT,011 SLTU,100 XOR,101 SRL,110 OR,111 AND; funct7=0x20 only 000 SUB / 101 SRA | rd=ALU(rs1,rs2); all other funct7/funct3 combinations illegal, including M |
| 0x0f | funct3=000 FENCE | in-order no-op after older memory; no rd; base FENCE reserved rd/rs1/fm fields are ignored as an author decode policy, no stronger relaxed ordering introduced |
| 0x0f | funct3=001 FENCE.I | illegal, including canonical encoding |
| 0x73 | exactly 0x00000073 ECALL,0x00100073 EBREAK,0x30200073 MRET | trap or return rules; other funct3=000 encodings illegal |
| 0x73 | funct3=001/010/011/101/110/111 | six CSR operations; CSR legality and write intent in Section 10 |
| 0x0b | enabled and funct3=0 and funct7=0 only | xdot4; other encodings illegal; all illegal when disabled |

Unlisted opcodes, unsupported extensions, reserved branch/load/store funct3, unsupported SYSTEM forms and malformed shift encodings create an illegal-instruction descriptor containing the full word. FENCE is serialized by the already ordered data path and needs no additional memory transaction. Neither software instruction names nor special PC/address constants affect decode. `misa` stays 0x40000100 in both configurations: the authorized custom instruction does not set the standard M extension bit or change the specified CSR value.

Source-use flags are decoded per operation: rs1 for ALU-immediate/load/JALR/store/CSR register forms; rs1 and rs2 for ordinary register ALU/branch/store/xdot4; no RF use for U/J/CSR-immediate/system no-source operations. Immediate fields occupying rs2 bit positions are never mistaken for dependencies.

## 7. Forwarding and load-use interlock

Source: source L9/L31/L33; acceptance L26/L43/L54–L55. Design group: `cpu.hazards`.

For each used EX source, select in program age order: x0 gives zero; newest older matching EX/MEM valid nonfaulting ready result (ALU/link/CSR/xdot4, or same-edge successfully completing load if used) next; matching MEM/WB valid normal rd-write result next; ID/EX operand snapshot last. A producer only matches if rd!=0 and it has real write intent. An unresolved matching EX/MEM load blocks use and must not fall through to an older MEM/WB value for the same rd. Two source selectors act independently. Branch comparisons, store address, store data, CSR register source and NPU req_a/req_b use these selectors. This handles consecutive writes to the same destination and dual-source dependencies without extra ALU bubbles.

ID read includes a same-edge WB-to-ID bypass. While ID/EX is held during a MEM wait, retiring WB values matching its used source indices refresh operand snapshots. This prevents a value lost from the WB forwarding network on an earlier wait edge from leaving stale operands in the held EX token. NPU accepted operands never change after acceptance; the NPU latches its own product operands.

Author choice: one decode load-use bubble. When a valid ID/EX load with rd!=0 will transfer to MEM and the valid ID token uses that rd, hold IF/ID and fetch_pc, consume the load toward EX/MEM, and insert an invalid ID/EX slot. Do not repeat this bubble on every wait edge: the load leaves ID/EX, and subsequent pauses are MEM ownership waits. On the successful response edge MEM/WB receives load data and younger stages resume immediately. The consumer subsequently uses MEM/WB forwarding. Independent control has no bubble. Thus the load-dependent retirement interval/span adds at most one edge for ALU, branch, store-address, store-data and xdot4 consumers, over identical memory waiting. Loads to x0 still execute/trap but cause no data interlock.

No interlock applies to ordinary ALU producers: immediate adjacency forwards from EX/MEM, one gap from MEM/WB or refreshed RF, x0 remains zero. No extra read/execute stage is allowed. For a MEM stall a younger ordinary EX token is held, older WB drains, and no younger store can issue. When a successful response and EX branch coincide, loaded data may be forwarded as needed; an error response kills that branch rather than redirecting it.

## 8. Data-memory protocol, lanes and cycle budget

Source: source L23/L25/L31/L33; acceptance L25/L44/L48/L52–L56. Design group: `cpu.memory`.

Only the oldest eligible EX/MEM memory token can own the port. Request valid requires EX/MEM.valid, memory operation, no pre-detected fault, mem_sent=0, reset inactive, and no older WB fault/MRET. Request fields come exclusively from the stable EX/MEM token. Valid and all fields hold unchanged through every edge with !dmem_req_ready. Request fire sets mem_sent once; request valid then deasserts even if ready remains high. One outstanding transaction, including stores awaiting a response. No unsolicited response is consumed: dmem_rsp_ready requires this owned sent transaction and space for its completion (WB always drains), reset inactive. A response is consumed only with valid&&ready, once. Earliest response is one edge after request acceptance, never the acceptance edge. Store responses are mandatory. No fabricated timeout exception is introduced for a violated environment response bound.

For effective byte address EA and lane l=EA[1:0], aligned bus address is EA&0xfffffffc. Alignment rules: byte always aligned; half requires EA[0]=0; word requires EA[1:0]=0. A bad alignment descriptor is formed in EX before any request; original EA, not aligned bus address, is reported as tval.

| Operation | Request write / wstrb / wdata | Successful response extraction |
| --- | --- | --- |
| LB/LBU | write=0,wstrb=0,wdata=0 | byte=(rdata >> (8*l))[7:0]; sign-/zero-extend respectively |
| LH/LHU | write=0,wstrb=0,wdata=0 | half=(rdata >> (8*l))[15:0], l=0 or 2; sign-/zero-extend |
| LW | write=0,wstrb=0,wdata=0 | all 32 bits |
| SB | write=1,wstrb=1<<l,wdata=(rs2&0xff)<<(8*l) | acknowledge only |
| SH | write=1,wstrb=3<<l,wdata=(rs2&0xffff)<<(8*l), l=0 or 2 | acknowledge only |
| SW | write=1,wstrb=0xf,wdata=rs2, l=0 | acknowledge only |

This is little-endian lane placement: lane 0 contains the lowest addressed byte. Ignored write lanes are driven zero as an author choice. A successful load or acknowledged store transfers into MEM/WB at the response edge. A response with err=1 converts the owning instruction to load/store access fault (5/7), original EA as tval, clears register-write/store-commit intent, flushes all younger tokens, and transfers the fault into MEM/WB. The external contract guarantees an erroneous store has made no memory modification; CPU cannot undo an external speculative write, so integration must enforce this guarantee. No younger data request is ever issued before older exception eligibility is resolved. A successful store may physically update memory at its request acceptance or successful response per the environment, but it has one ordered, irrevocable owner, and retires exactly once only after successful response. Older architectural effects drain before it; error response forbids the effect. Retirement store metadata must match its actual accepted write request, not reconstruct a different operation.

For cycle cost, let EX/MEM receive a memory token at e, first possible request handshake at h=e+1+d (d ready-delay edges), and response handshake at q=h+r (r=1..8). A nonmemory token would enter MEM/WB at e+1; the memory token enters at q. Therefore it adds exactly d+r MEM hold edges. At q the response data, EX advance, ID advance and eligible fetch replacement are processed together; no REQUEST_PREPARE or RESPONSE_RECOVER state is inserted. One load-use bubble if applicable is separate. Consecutive memory operations replace the old EX/MEM owner at q and request their own transaction at q+1; this is the usual next MEM cycle, not an extra recovery bubble.

Consequently an N-instruction no-control microprogram with M serial memory operations has retirement span no greater than `N + sum(d_i+r_i) + H`; for fixed conditions this is `N + M*(response_cycles+ready_delay) + H`. H=0 in independent control, H=1 for its single dependent consumer. Required pairs are (1,0),(8,0),(1,3). These are design targets, not a reported measured RTL result. Do not hide preparation/fetch/recovery cycles in external waiting. CSR serialization or NPU waits are not counted as ordinary ALU dependency bubbles; the base cycle fixtures contain neither NPU nor control-transfer penalties in this formula. Load-to-branch only uses the differential dependency allowance.

The environment supplies an external 256 KiB image mapped from 0x80000000 through 0x8003ffff. CPU has no built-in image-range check; boundary/protection errors are modeled by dmem_rsp_err. The maximum frozen ELF load end offset 0x342c0 fits that image; this is a source fact, not a newly inspected ELF. `tohost` at 0x8003f000 is a normal store to CPU, intercepted only by the environment (1=PASS, other nonzero=FAIL). No special address, program name or PC shortcut exists. FENCE cannot overtake an earlier outstanding response.

## 9. Precise faults and cancellation

Source: source L9/L21/L25/L27/L29; acceptance L27/L45/L64. Design group: `cpu.exceptions`.

Illegal decode and ECALL/EBREAK faults originate in ID; target/alignment faults in EX; data errors in MEM. Faults remain attached to instruction tokens. Architectural trap entry happens only when the oldest fault token reaches WB, after every older normal token has retired. As soon as a surviving fault is known, stop younger admission and invalidate younger tokens; never suppress older completion. A fault already known in EX/MEM has no data request. A wrong-path fault token is invalidated by its older legal redirect. Reset cancels all tokens, including a pending trap, without emitting a trap or commit.

| Fault | cause | trap_tval / mtval | fault PC |
| --- | ---: | --- | --- |
| taken branch/JAL/JALR target misalignment | 0 | target after JALR bit0 clearing | branch/jump PC |
| defensive bad fetch PC | 0 | attempted fetch address | that PC; mepc masks low bits as specified |
| illegal ISA, bad custom encoding, bad CSR address/write | 2 | full 32-bit instruction | offending instruction PC |
| EBREAK | 3 | 0 | EBREAK PC |
| load misalignment | 4 | original EA | load PC |
| load error response | 5 | original EA | load PC |
| store misalignment | 6 | original EA | store PC |
| store error response | 7 | original EA | store PC |
| ECALL in M-mode | 11 | 0 | ECALL PC |

Alignment is checked before request issuance, so access error cannot supersede a misalignment for the same instruction. Illegal instructions do not masquerade as memory operations. At WB trap: register writes and normal commit are disabled; mepc=PC&0xfffffffc, mcause=cause with interrupt bit clear, mtval=tval; MPIE=old MIE, MIE=0, MPP=3; fetch redirects to mtvec; all younger valid/held/issued state is cleared; trap_valid emits one edge with the descriptor. No asynchronous interrupt exists even when MIE=1.

An older MEM error defeats a younger branch or xdot at that edge. An older store/load must resolve successfully before a younger NPU request is accepted. CPU drives NPU kill on reset cancellation or any surviving flush that cancels the NPU owner; kill dominates potential request/response fire. EX branch flush only invalidates younger work: it must not cancel an older live NPU owner. In this in-order blocking design a younger branch cannot execute while an NPU owner occupies EX, so that case is prevented structurally. Defensive kill on trap/MRET may cancel an empty unit. No NPU response survives ownership cancellation, and no result is usable without the matching valid issued owner. Wrong-path stores never even issue data requests; speculative fetch alone is allowed.

## 10. CSR instructions and architectural updates

Source: source L21/L27; acceptance L28/L64. Design group: `cpu.csr`.

Author choice: serialize CSR operations and MRET at ID. Wait until all older ID/EX, EX/MEM and MEM/WB tokens have drained (including any memory response). Admit one CSR/MRET token, freeze younger decode/fetch through its WB completion, and permit only its normal advancement. This resolves CSR-to-CSR, CSR-to-trap and CSR-to-MRET dependencies without speculative CSR writes. Held fetch response remains valid as in Section 5; MRET WB discards it. This choice imposes no extra ALU dependency bubbles on programs without CSR. CSR register operands follow RF/WB rules; EX captures the committed old CSR value and computes pending new value. All CSR effects are applied only at WB with the token's normal retirement. A fault token performs no pending CSR operation.

| Address | Read / write policy | Reset |
| --- | --- | --- |
| 0x300 mstatus | read=(MIE<<3)|(MPIE<<7)|0x1800; write uses only bits3/7, fixes MPP=3; all other bits read0/write ignored | 0x1800 |
| 0x305 mtvec | RW, new=value&0xfffffffc; direct trap target | 0x80000000 |
| 0x340 mscratch | RW all bits | 0 |
| 0x341 mepc | RW, new=value&0xfffffffc | 0 |
| 0x342 mcause | RW all bits for software; hardware trap writes listed cause | 0 |
| 0x343 mtval | RW all bits | 0 |
| 0x301 misa | read-only constant0x40000100 | constant |
| 0xf14 mhartid | read-only constant0 | constant |

Only these addresses are legal. Read-only write attempt is illegal even if computed data equals the old value. Suppressed writes are legal reads. Let old be the committed CSR value, s the forwarded register source or zero-extended zimm. CSRRW/CSRRWI always have write intent and set new=s. CSRRS/CSRRSI set new=old|s; CSRRC/CSRRCI set new=old&~s. For set/clear register forms intent is `(encoded rs1 != 0)`, not `(runtime s != 0)`; immediate forms use `(zimm != 0)`. Thus a nonzero register containing zero still attempts a read-only write and traps. A write form with rd=x0 still writes the CSR; no RF destination write and commit_rd=0. CSR returns old to rd when rd!=0. CSRRW with rd=0 need not physically read its old value, but legality is still checked. After calculating new, apply the CSR-specific mask/fixed bits.

MRET is the exact instruction 0x30200073, normal retirement with no rd/memory write. At its WB edge MIE=old MPIE, MPIE=1, MPP=3, fetch_pc=mepc and younger tokens are flushed. CSR/trap/MRET cannot collide in the single WB slot. Ordered trap entry uses the latest previously retired mtvec/mstatus. `misa` write and `FENCE.I` trap per frozen task card even where frozen Sail reportedly differs; an independent task-specific boundary oracle is required. The locked external ISA revision is supplied by authorized-frozen-reference-metadata and recorded with exact hashes in Section17.2; it does not alter these explicit CSR rules.

## 11. Retirement outputs and effect correlation

Source: source L9/L29/L31; acceptance L36/L48; public fixture L68–L87. Design group: `cpu.retirement`.

Every valid normal MEM/WB token is consumed at one WB edge, writing RF and/or its pending CSR at that same edge and registering commit_valid=1. Commit PC/insn are the original fetched token, never a current fetch/decode value. For a true RF write to rd!=0: commit_rd=rd, commit_wdata=written result. For branch/store/FENCE/MRET or discarded x0 destination: commit_rd=0 and author choice commit_wdata=0. A load or xdot with rd=x0 still executes, may trap, and otherwise retires once. No instruction is skipped on the basis of x0.

For successfully acknowledged stores commit_mem_addr is the aligned dmem_req_addr, commit_mem_wstrb and commit_mem_wdata exactly equal the accepted request fields. This choice makes byte/halfword lane effects directly checkable by the port oracle. Original unaligned-to-word EA remains separately carried for exception tval. For every nonstore, commit_mem_wstrb=0 and author choice commit_mem_addr/commit_mem_wdata=0; these do not imply a load has no memory access. For no event, author choice event payload outputs are zero; consumers qualify by valid. Traps carry original PC/cause/tval and never increment normal-retirement count. Valids default clear every edge and are set only by consuming a live WB token. Adjacent events may be contiguous high cycles.

All successful stores have one request handshake, one response, one retirement; error stores have one request/response, zero memory effect, zero normal retirement and one trap. A normal ALU/CSR/xdot instruction has one retirement; killed tokens have none. Store side effects may precede the WB event by the real protocol interval, but must match ordered request ownership and cannot arise from a future/wrong-path/faulting token. No fixed commit postponement is used to simulate these effects. The test environment must drain accepted transactions before declaring PASS and compare final memory images. No trace collector/file is produced by the core author; these are public outputs for external sampling.

## 12. NPU arithmetic, handshake and exact n+2 response

Source: source L7. Design groups: `npu.interface`, `npu.arithmetic`, `npu.protocol`, `npu.cancel`.

`nebula_npu_dot4` ports are exactly input clk,rst_n,req_valid,req_a[31:0],req_b[31:0],rsp_ready,kill; output req_ready,rsp_valid,rsp_data[31:0]. All operate on core clock. Each accepted request is an independent dot product with no accumulator, DMA, memory access or saturation.

For i=0..3: a_i=signed(req_a[8*i+:8]); b_i=signed(req_b[8*i+:8]); p_i is their signed 16-bit product. Four parallel multipliers compute p0..p3. At acceptance latch those products. At the next edge pair0=sext17(p0)+sext17(p1), pair1=sext17(p2)+sext17(p3) into signed17 registers. At the following edge total=sext18(pair0)+sext18(pair1), latch rsp_data=sext32(total). All extensions occur before addition. Range of exact result is [-65024,65536], so signed18 suffices; 16-bit wrapping or treating bytes as unsigned is forbidden. Little byte lane0 is bits7:0. INT32 results are two's-complement signed sums; the maximum 65536 must not become zero.

Author implementation FSM with four phases:

| Pre-edge phase / condition | Outputs during cycle | At next active edge |
| --- | --- | --- |
| any, !rst_n | req_ready=0,rsp_valid=0,rsp_data=0 | async clear phase/data/valid |
| any, kill | req_ready=0,rsp_valid=0 | clear phase=IDLE and valid/data; ignore both handshakes |
| IDLE, no request fire | req_ready=1,rsp_valid=0 | hold IDLE |
| IDLE, req_valid&&req_ready | ready=1,valid=0 | latch p0..p3, phase=P0 |
| P0 | ready=0,valid=0 | latch pair sums, phase=P1 |
| P1 | ready=0,valid=0 | latch total/result, phase=RSP |
| RSP, !rsp_ready | ready=0,valid=1,data=registered result | hold phase/result |
| RSP, rsp_ready | ready=0,valid=1,data=registered result | consume once, phase=IDLE, clear response validity |

Equations: `req_ready = rst_n && !kill && phase==IDLE`; `rsp_valid = rst_n && !kill && phase==RSP`; req_fire=req_valid&&req_ready; rsp_fire=rsp_valid&&rsp_ready. Phase priority: reset, kill, phase transitions, hold. Product and pair registers hold except their indicated transition; response register holds through all unconsumed RSP edges. Data after consumption may hold the old value but is not valid; author choice clear on kill/reset. There is deliberately no acceptance on the response-consumption edge: at most one outstanding operation including a held response. A new request can be accepted at the following edge if presented.

Accepted at edge n: after n phase=P0; after n+1 phase=P1; after n+2 phase=RSP and valid/data are observable. rsp_ready already high does not consume a newly assigned valid at n+2: earliest external consumption is edge n+3. With backpressure after n+2, both valid and data remain stable until an actual fire. Kill at n, n+1, n+2 or any held-response edge cancels all work; it suppresses readiness/valid before that edge and prevents a stale acceptance or consumption. Lowering kill later exposes IDLE, not a canceled result. A request presented continuously can begin a new operation only via a later IDLE fire. Reset has the same cancel effect and may assert between edges.

| Edge | CPU/NPU action |
| --- | --- |
| m | NPU products accepted, owner remains in ID/EX; younger freeze |
| m+1 | NPU pair sums; older CPU stages drain |
| m+2 | NPU result valid after edge; CPU cannot sample new sequential valid at that same edge |
| m+3 | CPU response handshake; result+owner enters EX/MEM; younger can resume ID/fetch |
| m+4 | owner enters MEM/WB |
| m+5 | RF write / one commit; rd=x0 instead discards write and still commits |
