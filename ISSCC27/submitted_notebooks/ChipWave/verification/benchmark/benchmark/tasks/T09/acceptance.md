# T09：CPU 验收计划

本计划为[T09 任务卡](task.md)的强制附件。RISC-V 官方 [ACT4](https://github.com/riscv/riscv-arch-test) 用于测试声明支持的架构规则；该项目明确说明 ACT 不是处理器完整验证。五级流水线的旁路、停顿、冲刷及不同存储器时序由本计划的独立测试验收。

## 固定执行环境

- ISA：RV32I、Zicsr、题目所列 M-mode CSR/异常/MRET；无压缩、乘除、浮点、原子、MMU 和异步中断。实际 `misa`、UDB、Sail 配置必须一致。锁定的 ACT4 配置和制品见 [`benchmark/cpu/act4/`](../../cpu/act4/) 与[制品清单](../../../evaluator/act4_elfs/MANIFEST.json)。
- 复位入口 `0x8000_0000`；指令与数据镜像为 256 KiB。`0x8003_F000` 是 testbench 截获的 32-bit `tohost` 写寄存器；写 1 PASS，写其他非零值 FAIL。所有程序必须在有限步数内向此地址写结果，或由测试器根据退休轨迹判定；超时为 FAIL。锁定 ACT4 的 45 个 RV32I/Zicsr ELF 中最大装载结束偏移为 `0x342c0`；外部存储器不计入核面积。
- `rvmodel_macros.h` 把 ACT4 的 PASS/FAIL 宏转换为 `tohost` 写；`link.ld` 把代码、数据、栈和异常向量放在镜像内，预留 `tohost`。ACT4 还需 UDB、Sail 与框架配置。框架生成 ELF 后，由同一个 ELF 加载器为 DUT 和参考模型建立等价的存储器初始状态。RISC-V 工具链、ACT4、Sail 和 ISA 手册修订均从[sources.lock.yaml](../../sources.lock.yaml)与正式镜像锁定。
- `tohost` 是环境终止机制，不是 ISA 指令；CPU 不能识别测试名、PC 值或终止地址并跳过正常执行。程序或数据访问测试内存边界时，由数据响应错误建模；测试器不得从不存在的硬件功能推断通过。

## A. 官方 ACT4 架构测试

测试组 ID 为 `CPU-ACT`。锁定配置将 `include_priv_tests=false`，生成并运行该配置所适用的**全部** RV32I 与 Zicsr 测试；M-mode 的有限 CSR/异常/MRET 集合由 B/D 组按题卡独立验收，不能借此宣称完整 Sm 认证。当前已用锁定 ACT4 修订、Sail 0.14.1 与 RV32 GCC 16.1 生成 45 个 ELF，连同 hash 和配置快照列在[ACT4 制品清单](../../../evaluator/act4_elfs/MANIFEST.json)。[Sail 参考运行器](../../../evaluator/check_act4_sail.py)已验证全部 45 个 ELF 均执行到 `tohost=1`，逐项步数与轨迹哈希记录在[参考结果](../../../evaluator/act4_elfs/SAIL_RESULTS.json)。仓库中的[独立评测器](../../../evaluator/t09_check.py)使用这些 ELF 对应的压缩提交 oracle（合计 113,280 条提交、441 次 store），并以评测方总线平台采集的提交端口逐条比对；五级参考 CPU 已 45/45 通过这一组。该证据只验证 `CPU-ACT` 组，不能代替定向异常、总线等待和随机差分组。所有清单内 ELF 必须报告 PASS，不能以删除失败文件提高通过率。若 ACT4 的某个测试需要本题明确排除的功能，只能在生成前由 UDB/功能范围自然排除，并在报告中列出，不可临时跳过。官方 ACT4 可能更新覆盖点或参考模型，正式榜单必须锁住版本及生成文件。

ACT4 分配在 F 的 10 分里；不足以验收五级结构、时序相关 hazard、总线背压、长程序状态或未知错误。通过本项目中的适用子集只能称为“该配置下通过 ACT4 子集”，不能称作 RISC-V 认证。

## B. 自编定向程序集

每个程序保持可人工审查，包含明确初始状态、预期提交序列与终止写。下表列出**至少**应实现的独立测试模板；每个模板须有关键值变体（零、全 1、符号边界等），而非只跑一个常数。

| 组 ID | 类别 | 至少模板数 | 必测情形 |
| --- | --- | ---: | --- |
| CPU-DIR-INT | 整数与控制流 | 12 | 所有 RV32I 算术/逻辑/移位操作族；有符号/无符号比较；LUI/AUIPC；六种分支的取与不取；JAL/JALR，JALR bit0 清除；x0 写入忽略 |
| CPU-DIR-MEM | 访存 | 10 | LB/LBU/LH/LHU/LW 的符号扩展；SB/SH/SW 的 byte lane；同地址读写、字边界、最高地址；读写存储器响应等待；FENCE 的有序效果 |
| CPU-DIR-HAZ | 数据相关 | 12 | EX→EX、MEM/WB→EX、双源同一寄存器、load-use 一拍停顿、load→branch、load→store 数据、连续写同一 rd、x0 不旁路 |
| CPU-DIR-TRAP | 冲刷与异常 | 12 | 取/不取分支紧邻 store；JAL/JALR 的错误路径；分支与 load-use 相邻；非法指令、ECALL、EBREAK、访存非对齐、数据访问错误；异常后 MRET；年轻 store 不得提交 |
| CPU-DIR-CSR | CSR | 8 | CSRRW/CSRRS/CSRRC 及三个 immediate 形式；rd=x0 或 rs1=x0；只读 CSR 写非法；mstatus 进出异常；mepc/mtval/mcause；mtvec 直接模式 |

一个模板可以包含多个指令，但分值按独立现象分配。54 个模板的双变体程序和对应 oracle 随[验收制品](../../../evaluator/t09_data/programs/directed/)公开，但不复制进受测 Agent 的任务工作区；任务包中的端口冒烟只提供简化例子。定向程序要检查内存副作用、寄存器最终值和逐条提交，而非仅依赖 `tohost=1`。

## C. 提交级随机差分

测试组总类为 `CPU-DIFF`，计分时按 `CPU-DIFF-INT`、`CPU-DIFF-MEM`、`CPU-DIFF-TRAP` 三个互斥的程序类别出结果；各类别的通过数与总数分别写入评分输入，不能把一个类别的成功补给另一个类别。用独立生成器创建至少 100 个固定种子的有界程序，每个有效程序退休至少 1,000 条指令，合计至少 100,000 条退休指令。生成器显式控制合法地址、初始化寄存器、循环上界、CSR 可写掩码，并为异常测试保留单独模式；不能以 DUT 输出作为期望值。参考端用与题目配置相符的 [Sail RISC-V 模型](https://github.com/riscv/sail-riscv) 执行同一 ELF，生成逐条退休轨迹。

比较器按**退休顺序**比对 PC、指令字、目的寄存器、写回值、store 地址/字节使能/数据和异常三元组；不要求相同周期。比较器另外校验 `commit_valid` 不重复、不跳号、不把错误路径指令当作退休，所有已接受存储器请求有唯一响应，程序结束时 DUT 与参考内存镜像相同。首次失配输出种子、ELF hash、前后各 20 条提交和相关总线事务，便于复现。随机分数由预先固定的种子组按通过率档位计入 F/P，不允许参赛者挑选种子。

## D. 五级流水线及总线专项

| 组 ID | 检查 | 验收方法 |
| --- | --- | --- |
| CPU-PIPE-LAT | 取指至退休延时及连续吞吐 | 一周期指令存储器下，64 条无相关 ADDI 中每条取指请求在边沿 `n` 采样，其对应提交在边沿 `n+4` 后出现；取指与退休分别连续每拍一条，不得提前、滞后、重复或丢失 |
| CPU-PIPE-HAZ | 前递、相关气泡与短程序周期 | 为 B 组 hazard 生成紧邻与插空版本，检查退休结果、相关气泡及无控制流微程序总周期；ALU 相关额外气泡为 0，load-use 最多 1；不强制旁路电路编码，按下面的 port_timing_v1 规则测量 |
| CPU-PIPE-MEM | 存储器等待 | 数据端 ready/response 延迟在 1–8 周期内由评测方固定种子变化；请求在阻塞期间稳定，响应不重放，其他流水级暂停或冲刷正确 |
| CPU-PIPE-FLUSH | 控制转移 | 在目标与顺序路径放不同 store 标记；取分支/JAL/JALR/异常后只有正确路径的标记可到达内存 |
| CPU-PIPE-RESET | 复位 | 复位从空闲、ALU 流、load 等待、分支附近注入；环境同时清空总线在途事务。释放后从复位 PC 重新开始，无旧提交 |

**延时采样约定**：测试平台在边沿 `n` 前采样 `imem_valid/imem_addr`，在同一边沿的非阻塞赋值稳定后采样 `commit_valid/commit_pc`。一周期存储器在边沿 `n` 接收请求，其响应在下一周期供 CPU 使用；典型 IF/ID、ID/EX、EX/MEM、MEM/WB 逐级推进后，提交观察口在 `n+4` 边沿后有效。64 条 ADDI 的每个 PC 均单独核对，不靠平均吞吐率推断延时。固定输入波形和输出 trace 的[延时检查器](../../../evaluator/cpu_latency_check.py)与[公开 RTL 冒烟](../../../evaluator/public/tb_T09.sv)已实现；[ELF 总线平台](../../../evaluator/public/tb_cpu_elf.sv)和[提交比较器](../../../evaluator/sail_commit.py)也已接入。平台逐笔核对退休 store 与真实总线写握手，并在结束时检查无遗留写事务。

### port_timing_v1：周期性能检查（2026-10-09 补充）

[独立周期检查器](../../../evaluator/t09_timing_check.py)和[固定端口 testbench](../../../evaluator/t09_timing_tb.sv)不读取 DUT 层次或其内部 stall 信号。22 项检查包括连续 ADDI、6 对 ALU/x0 程序，以及 5 类 load 相关在 3 种总线条件下的 15 对程序。条件 `(response_cycles, ready_delay)` 固定为 `(1,0)`、`(8,0)`、`(1,3)`；ready_delay 从请求首次有效起计算，响应从请求握手起计算并保持到接收。每次运行重置 CPU 和存储器。

- **“load-use 一拍”是相关额外气泡，不是整个 CPU 遇到 load 只能暂停一拍。**相关/无相关程序仅改变消费者的源寄存器，指令数、总线条件、控制流方向均相同。分别比较 `消费者退休周期−生产者退休周期` 和整段退休跨度；两个差值均不得超过 1。普通 ALU 相关的两个差值均不得超过 0；更快的实现不因少停一拍而失败。
- **不能只测差值。**无控制流程序的退休跨度 `last_commit−first_commit+1` 不得超过 `N + M×(response_cycles+ready_delay) + H`，其中 `N` 是正常退休指令数，`M` 是串行访存次数，`H` 是本微程序允许的 load-use 气泡数（无相关为 0、单个相关为 1）。此总周期上限是本次新增的量化性能要求，不应追溯宣称旧题面已经明文规定。实现自身的访存准备、取指恢复或返回数据延迟不能冒充外部总线等待。
- **功能仍须正确。**独立小型 ISA oracle 校验每条退休的 PC/指令/写回及 store；真实总线事务数、写入内容、最后内存状态也须一致，错误路径不能发数据请求，未完成事务不能作为通过。
- 22 项统一计入独立 `CPU-PIPE-CYCLES` 组（评分版本 `t09_group_cycles10_v1`），占归一化 10 分：22/22 得 10 分，11–21/22 得 5 分，0–10/22 得 0 分；安全缺陷按通用规则使所在子项为 0。任意一项失败，该组至少少得 5 分，但不会逐例累计扣 5 分。其余原有组按原比例缩放至合计 40 分；`CPU-PIPE-HAZ` 保留原 8 项功能检查，`CPU-PIPE-LAT` 保留原独立延时测试，周期失败不再次合并进这两组。分支/JAL/JALR 另报告取/不取的退休间隔，不设临时罚拍门槛；load→branch 仅检查相关增量，不套用无控制流总周期公式。
- 本检查覆盖固定微程序，不等于完整应用性能基准，也不能从端口周期数推断某个内部 stall 信号持续了多久。参考与所有候选同等适用；历史成绩须显式区分检查器版本，不能把旧组全过当成 v1 全过。

2026-10-09 已优化并重新冻结参考 RTL：归一化功能 **50/50**、`port_timing_v1` **22/22**、21 个可编译缺陷变异体全部检出。普通 ALU 相关不增加周期，15 组 load 相关程序均只增加 1 拍；连续 ADDI 逐条取指到退休为 4 拍，稳态 IPC=1。完整周期、源代码 hash 和总线证据见 [`t09_timing_qualification.json`](../../../evaluator/t09_timing_qualification.json)，冻结资格见 [`t09_qualification.json`](../../../evaluator/t09_qualification.json)。ASAP7 WC、1 GHz、统一参数下，seed 11/29/47 的最终布线 setup 裕量分别为 +9.353/+14.899/+9.008 ps，hold 与 DRC 均通过；三种子均用冻结 workload 做了 1 GHz 门级活动功耗采集，标注率为 100%。原始报告位于 [`evaluator/fixtures/t09_cpu_20261009_cycles10`](../../../evaluator/fixtures/t09_cpu_20261009)。旧参考最初 6/22 的发现属于历史记录，不能替代新版资格；历史候选成绩未自动重算。

公开的独立评测器已生成 54 个定向模板的 108 条双变体 ELF 与 100 条固定种子长程序。后者合计 151,801 条 Sail 步进、1,089 次异常，每条至少 1,271 步；参考五级 CPU 对 ACT4 45/45、定向 108/108、长程序 100/100 的提交/异常轨迹比对通过。另以 20 个固定总线时延种子对四条重点程序做了 80 次差分，全部通过，1–8 周期响应延迟均出现，累计 9,789 个请求背压周期；在 ALU、分支和两种 load 等待状态注入运行中复位的四项专项也通过。题卡与 Sail 不一致的四条非法指令专项已用独立题卡 oracle 校准并通过；21 个可编译 CPU 缺陷变异体均被对应定向用例检出。[`t09_check.py`](../../../evaluator/t09_check.py)已把这些功能组接入统一评分器，当前参考 RTL 归一化功能分为 50/50，并已独立通过上述 22 项周期门槛；重新资格验证后的三种子 1 GHz 物理基线已录入[PPA 清单](../../ppa-baselines.json)。这仍是任务级校准，不代表整套 benchmark 已获正式发布资格。

已发现两个题卡与当前 Sail 行为不同的边界：题卡规定写 `misa` 为非法指令、`FENCE.I` 不支持且触发非法指令；锁定 Sail 在本配置下分别忽略前者写入、执行后者。独立评测器已为这两个边界各建立两条题卡专属程序，逐项检查 trap 的 PC/cause/tval、错误路径 store 不退休、异常处理后 MRET 回到 PASS；五级参考 CPU 4/4 通过。Sail 在这两个边界上的结果不能直接当作标准。

**固定延时本身不能数学上证明内部级数。**自动评分以 `CPU-PIPE-LAT`、hazard、冲刷、等待和提交差分检查可观察的五级时序行为；四组级间寄存器仍是设计要求，但不因不可自动核验的内部编码给人工结构分。若今后加入静态网表检查，须先公开机器可判定的规则和误判回归，再冻结评测配置。

随机等待测试最少 20 个时延种子，每个程序的最大仿真时钟周期设为该程序 Sail 退休步数的 100 倍加 10,000；长程序上限可单独在清单中固定，但不能运行中改变。超过上限记超时，不据此推断具体逻辑错误。

## 发布前验证 CPU 验收器

1. 用已知可工作的独立 RV32I 五级流水线参考实现运行 A–D，生成完整日志；参考实现源码随仓库公开，但不得复制进受测 Agent 的任务工作区。
2. 为每一种 hazard、异常和总线握手制造至少一个可编译缺陷变异体；对应测试必须失败，且失败原因与规范一致。
3. 检查 ACT4 生成的所有 ELF 不使用被排除的 ISA 扩展或中断环境；记录纳入/排除数量、原因和 hash。
4. 用相同程序对 DUT 比较器与 Sail 跑一次全量回归；复查首次失配定位是否给出可重放证据。
